# ИИ-консультант Аким

Отдельный сервис для backend команды: получает сообщение, историю и актуальное состояние игры, возвращает основной ответ, сильные стороны, риски, рекомендации и уточняющий вопрос. Историю, пользователей и рассчитанные результаты хранит основной backend. Консультант не рассчитывает Score и не изменяет игру.

## Быстрый запуск

Проверенный вариант — Python 3.12. После клонирования выполняйте команды из корня репозитория. Активация виртуального окружения не нужна.

**Windows / PowerShell:**

```powershell
py -3.12 -m venv ai_service/.venv
& ./ai_service/.venv/Scripts/python.exe -m pip install -r ai_service/requirements-lock.txt
if (-not (Test-Path ai_service/.env)) {
    Copy-Item ai_service/.env.example ai_service/.env
}
```

**Linux / macOS:**

```sh
python3.12 -m venv ai_service/.venv
ai_service/.venv/bin/python -m pip install -r ai_service/requirements-lock.txt
test -f ai_service/.env || cp ai_service/.env.example ai_service/.env
```

Откройте `ai_service/.env` в редакторе и заполните первые две строки:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=название_доступной_модели
OPENAI_TIMEOUT_SECONDS=45
OPENAI_MAX_OUTPUT_TOKENS=4000
```

`OPENAI_MODEL` — техническое название модели для API, отдельный числовой ID не нужен. Значения `ваш_ключ` и `название_доступной_модели` — пояснения: замените их своими данными. Ключ хранится только в локальном `.env`, который исключён из Git. В репозитории передаётся `.env.example` с пустыми полями. Приложение не сохраняет в файл значения, ранее введённые в PowerShell.

Запуск на Windows:

```powershell
& ./ai_service/.venv/Scripts/python.exe -m uvicorn ai_service.app:app --host 127.0.0.1 --port 8001
```

Запуск на Linux / macOS:

```sh
ai_service/.venv/bin/python -m uvicorn ai_service.app:app --host 127.0.0.1 --port 8001
```

Откройте http://127.0.0.1:8001/docs — интерактивную документацию с точными схемами. `GET /health` доступен без ключа. Без ключа или модели `POST /chat` возвращает `503 ai_not_configured`. После изменения `.env` перезапустите процесс сервиса.

`requirements-lock.txt` фиксирует проверенные версии, включая транзитивные и тестовые зависимости. `requirements.txt` содержит только прямые зависимости запуска, `requirements-dev.txt` дополнительно подключает тесты.

Если передаёте команде только папку `ai_service`, запускайте из её родительской папки либо из самой папки командой:

```powershell
& ./.venv/Scripts/python.exe -m uvicorn ai_service.app:app --app-dir .. --host 127.0.0.1 --port 8001
```

Название модели не зашито в код: укажите модель, доступную вашему API-проекту и поддерживающую Responses API со структурированным JSON. Доступность и качество конкретной модели проверяются живым запросом. Подмена модели не требует изменения промпта или backend-контракта, но требует повторной проверки качества.

Приложение автоматически читает **только `ai_service/.env` рядом с `config.py`**, независимо от текущей папки терминала. Переменные окружения процесса имеют приоритет над файлом — это позволяет DevOps передавать секреты средствами сервера. Если ранее задавали `$env:OPENAI_API_KEY` или `$env:OPENAI_MODEL`, откройте новый терминал без этих переменных либо удалите их перед запуском с `.env`. Подстановка `${VARIABLE}` внутри значений файла отключена; записывайте значения целиком.

Дополнительные настройки:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `OPENAI_TIMEOUT_SECONDS` | `45` | Общий предел ожидания вызова, больше 0 и не более 120 секунд |
| `OPENAI_MAX_OUTPUT_TOKENS` | `4000` | Лимит выходных токенов, 256–16000; слишком маленький лимит может дать неполный ответ |

Начальный сервис доступен только локально. Межсервисная авторизация и публикация согласуются при интеграции; API-ключ остаётся у консультанта, не отправляется frontend. Не публикуйте этот локальный прототип как открытый неавторизованный API.

## Развёртывание для DevOps

1. Клонируйте репозиторий, установите Python 3.12 с поддержкой `venv`, выполните установку из `requirements-lock.txt` по инструкции выше.
2. Создайте `ai_service/.env` из шаблона и заполните его на сервере либо передайте те же переменные через менеджер процессов/секретов. На Linux ограничьте доступ: `chmod 600 ai_service/.env`.
3. В менеджере процессов задайте рабочую папку — корень клона; команду — абсолютный путь к `ai_service/.venv/bin/python` с аргументами `-m uvicorn ai_service.app:app --host 0.0.0.0 --port 8001`. Включите перезапуск при сбое. `0.0.0.0` используйте во внутренней сети, доступной основному backend; при reverse proxy на той же машине достаточно `127.0.0.1`.
4. Для проверки процесса вызывайте `GET /health`. Основной backend обращается к `POST /chat` по внутреннему адресу этого сервиса. Для вызовов модели серверу нужен исходящий HTTPS-доступ к `api.openai.com`.
5. После изменения конфигурации перезапускайте сервис. Health не проверяет ключ и доступ к модели — их проверяет реальный запрос `POST /chat`.

Сервис не требует собственной базы данных или локальных пользовательских файлов. История приходит в запросах от основного backend. Конкретные пути зависят только от места клонирования, пути компьютера автора в настройках не используются.

## Первый запрос

В другом терминале, из корня репозитория:

```powershell
$payload = Get-Content -Raw -Encoding UTF8 ai_service/examples/chat-request.json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8001/chat `
  -ContentType 'application/json; charset=utf-8' `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($payload)) | ConvertTo-Json -Depth 10
```

Для анализа проверенного сценария замените имя файла на `ai_service/examples/chat-with-result.json`. Это синтетический пример: стоимость 95, Score 52.55768 → 56.54307, критических значений после нет. Эффекты в файле уже рассчитаны; приложение не вычисляет их повторно.

## Контракт с backend

`POST /chat` принимает один JSON:

```json
{
  "message": "Что слабее всего в Нуре?",
  "history": [
    {"role":"user","content":"Рассматриваем социальную инфраструктуру"},
    {"role":"assistant","content":"Уточним исходные показатели района."}
  ],
  "context": {
    "selected_measures": [],
    "budget_remaining": 100,
    "simulation_result": null
  }
}
```

- `message`: 1–4000 символов после удаления пробелов по краям. Новое сообщение не дублируется в истории.
- `history`: максимум 20 сообщений `user`/`assistant`, каждое 1–4000 символов. Системные роли и неизвестные поля запрещены.
- `selected_measures`: максимум 5 разных ID `M1`–`M14`, с `district_id`. Для городских `M2`, `M6`, `M12`, `M14` район равен `null`; для остальных — `esil`, `almaty`, `saryarka`, `baikonur` или `nura`.
- `budget_remaining`: число 0–100, без строковых чисел, boolean, NaN или Infinity.
- `simulation_result`: `null` до актуального расчёта либо объект, показанный целиком в `examples/chat-with-result.json` и `/docs`. Все пять районов уникальны, у каждого все десять показателей до и после. Критические пары имеют значение строго меньше 40. `effects` содержит непосредственные эффекты с одним ID или синергии с двумя разными ID.

Backend обнуляет `simulation_result` при изменении выбора, пока не пересчитает сценарий. Проверка арифметики, бюджета относительно стоимости, конфликтов мер и допустимости финального набора остаётся в основном backend. В чате можно обсуждать незавершённый выбор.

Успешный HTTP 200 возвращает всегда пять полей:

```json
{
  "answer": "Краткий ответ пользователю.",
  "strengths": [],
  "risks": [],
  "recommendations": [
    {"title":"Рассмотреть социальные объекты","explanation":"Предложение с пояснением на основании переданных данных."}
  ],
  "follow_up_question": null
}
```

`strengths`, `risks` и `recommendations` содержат от 0 до 5 объектов `title` (1–160 символов) и `explanation` (1–1200). `answer` — 1–6000 символов; вопрос — `null` либо 1–500 символов. Пустые блоки frontend может не отображать. `/chat` выдаёт ответ целиком после проверки; для постепенного текста используйте `/chat/stream`. Текст выводите как текст, не вставляйте через `innerHTML`.

Backend сохраняет полный JSON. Для следующего запроса превращает нужные непустые блоки в сообщение `assistant`, сокращая его до 4000 символов при необходимости. Полная версия отчёта при этом остаётся в базе backend. Данный сервис не хранит диалоги и не использует OpenAI conversation IDs.

## Стриминг для backend

`POST /chat/stream` принимает **тот же JSON**, что и `/chat`. Ответ — `Content-Type: text/event-stream`, обычное HTTP-соединение без WebSocket. Один запрос к сервису делает один запрос к модели; автоматического повтора нет.

События разделены пустой строкой. `data` в каждом событии — отдельный JSON:

```text
: connected

event: answer_delta
data: {"delta":"В Нуре "}

event: answer_delta
data: {"delta":"улучшились социальные показатели."}

event: complete
data: {"answer":"В Нуре улучшились социальные показатели.","strengths":[],"risks":[],"recommendations":[],"follow_up_question":null}

```

Пример иллюстрирует формат событий. Содержимое реального ответа определяется переданным сценарием.

| Событие | Действие клиента |
| --- | --- |
| `answer_delta` | Добавить `data.delta` к временному тексту ответа. Это уже декодированный текст, а не кусок JSON модели |
| `complete` | Заменить временный текст на `data.answer`, показать все итоговые блоки и сохранить полный `data` как ответ консультанта |
| `error` | Прекратить ожидание, показать `data.error.message`; частичный текст пометить как незавершённый и не сохранять как готовый ответ |

Строки, начинающиеся с `:`, — комментарии SSE; клиент их пропускает. Первое `connected` означает только открытие потока, не появление текста модели. В успешном запросе приходит ровно один `complete`, только после полной проверки всех пяти полей. Неполные JSON-блоки рисков и рекомендаций клиенту не передаются. Финальный текст может отличаться от чернового нормализацией пробелов.

Невалидный запрос получает обычный HTTP 422 с JSON-ошибкой; отсутствие ключа/модели — HTTP 503. После открытия потока статус уже HTTP 200, поэтому ошибки OpenAI, таймаут, отказ модели и неверный итог передаются **событием `error`**, например:

```text
event: error
data: {"error":{"code":"ai_timeout","message":"Превышено время ожидания ответа ИИ."}}

```

Окончание соединения без `complete` или `error` тоже считается сбоем, а не успешным ответом. Повторный запрос выполняется только по явному действию пользователя и может расходовать токены заново. До `complete` текст является предварительным: окончательная проверка отчёта ещё не выполнена.

Для frontend с POST-телом используйте `fetch` и чтение `response.body`; обычный `EventSource` работает через GET. UTF-8 декодируйте потоковым `TextDecoder`, а SSE — с буфером до пустой строки: сетевой чанк не обязан совпадать с событием или границей символа. Кнопка «Стоп» отменяет fetch через `AbortController`. Backend должен закрыть свой запрос к ИИ-сервису, когда клиент отключился; сервис закрывает поток OpenAI. Уже выполненная генерация всё равно может быть оплачена.

**DevOps:** проксируйте поток без накопления всего тела. Сервис отдаёт `X-Accel-Buffering: no` и `Cache-Control: no-cache, no-transform`; проверьте, что backend, reverse proxy и сжатие не буферизуют SSE. Для Nginx у маршрута потока можно явно задать `proxy_buffering off;` и `proxy_read_timeout 130s;` (больше максимального разрешённого таймаута модели 120 секунд). Не устанавливайте собственный `Content-Length`. Действующий Uvicorn отслеживает отключение клиента во время ожидания модели.

Проверка из PowerShell, из корня репозитория (один платный запрос):

```powershell
curl.exe -N -X POST http://127.0.0.1:8001/chat/stream -H "Content-Type: application/json" --data-binary "@ai_service/examples/chat-request.json"
```

Linux / macOS — та же команда с `curl` вместо `curl.exe`. `-N` отключает буферизацию вывода curl. Swagger удобно использовать для схем, но для наблюдения постепенной передачи используйте curl или потоковый HTTP-клиент. Стриминг уменьшает ожидание начала текста; время полного ответа и задержка до первого токена зависят от модели. Настройка reasoning и модель в этой правке не менялись.

## Ошибки

```json
{"error":{"code":"ai_not_configured","message":"Для консультанта не настроены API-ключ или модель."}}
```

| HTTP | Код | Значение |
| --- | --- | --- |
| 422 | `invalid_request` | Невалидные JSON, поля, значения или роли; сверить запрос с `/docs` |
| 503 | `ai_not_configured` | Не заданы ключ или модель |
| 503 | `ai_unavailable` | Сетевая ошибка, отказ доступа, лимит запросов либо другая ошибка провайдера |
| 504 | `ai_timeout` | Истёк общий срок ожидания или сетевой таймаут |
| 502 | `invalid_ai_response` | Неполный ответ, неверный JSON либо нарушение выходной схемы |
| 502 | `ai_refusal` | Модель отказалась формировать отчёт |

Автоматические повторные платные вызовы отключены. Ответы ошибок не содержат секретов, сырых сообщений провайдера или текста входного запроса. Health проверяет только процесс, не кредиты и не доступ к модели.

## Проверка

```powershell
& ./ai_service/.venv/Scripts/python.exe -m pytest ai_service/tests -q
```

Тесты не требуют ключа и сети. Они проходят через настоящий OpenAI SDK и FastAPI, заменяя только HTTP-транспорт провайдера. Проверяют форму сетевого запроса, строгие схемы, результаты, ошибки, таймаут, отсутствие повторов и изоляцию одновременных диалогов. Это не доказательство фактической точности живой модели.

Для живой проверки используйте семь вопросов и ожидаемые свойства из `examples/evaluation.json`. Каждый такой запрос расходует API-токены. Перед показом жюри проверьте реальные ответы выбранной модели, особенно отказ выдумывать Score и приоритет нового состояния над старой историей.

## Файлы

| Файл | Назначение |
| --- | --- |
| `app.py` | HTTP-маршруты, ошибки и жизненный цикл клиента |
| `schemas.py` | Общий контракт и структурная валидация |
| `provider.py` | Вызов Responses API, общий таймаут и проверка ответа |
| `streaming.py` | Извлечение частичного текста, события SSE и закрытие потока |
| `knowledge.py` | Отдельная сборка истории и актуального снимка |
| `prompts/consultant.txt` | Поведение и ограничения советника |
| `data/city.json` | Синтетический справочник районов и мероприятий |
| `config.py`, `errors.py` | Настройки процесса и публичные ошибки |
| `examples/` | Запросы для команды и ручная оценка качества |

Данные перенесены из [предоставленного датасета](https://docs.google.com/document/d/1Uc-GdGoKhDY-spu8V50-ZMm33t2CjYLP/preview). Его правила допускают до двух мер из одного направления; это отличается от возможной трактовки первоначального кейса «по одной мере каждого направления». Статус правил уточняется у организаторов; консультант не является финальным игровым валидатором.

Интеграция использует [Responses API](https://developers.openai.com/api/docs/quickstart) и [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). `store=False` отключает сохранение Response для последующего получения через API; это не утверждение об отсутствии иных служебных логов провайдера. Полная игровая модель, интеграция с 3D-демо, голосовой режим, RAG и обучение модели не входят в этот сервис.
