При показе карты сохраняйте видимую атрибуцию «© OpenStreetMap contributors» и ссылку на ODbL. Данные получены через [Overpass API](https://overpass-api.de/api/interpreter) и для части контуров зданий через [официальный OSM API](https://api.openstreetmap.org/api/0.6/map). Каждый файл — GeoJSON `FeatureCollection`. Геометрия: `Polygon`/`MultiPolygon` для районов, `LineString` для дорог и рек, `Polygon` для парков и зданий. Координаты — **WGS84 EPSG:4326**, порядок `[longitude, latitude]`. В `properties` у каждого объекта есть `layer`, `districtId`, `osmType`, `osmId`; у дорог — `highway` и доступные теги `name`, `bridge`, `lanes`, `oneway`; у рек — `isEsil` и доступное название; у зданий — доступные `building`, `height`, `levels`. Отсутствующие в OSM теги представлены как `null`. ID районов: `esil`, `almaty`, `saryarka`, `baikonur`, `nura`.

Используйте `isEsil: true`, если нужен только Есиль. В `roads.geojson` включены классы OSM `motorway`, `trunk`, `primary`, `secondary`, `tertiary`. Сервисные и жилые улицы в этот облегчённый слой не включались.

## Локальные x/z для Unity

Начало локальной системы: **(lon₀, lat₀) = (71.43°, 51.16°)**. Для каждой WGS84 точки `[lon, lat]`:

```text
R = 6_378_137 м
xMeters = R × radians(lon − lon₀) × cos(radians(lat₀))
zMeters = R × radians(lat − lat₀)
yMeters = 0
```

Это локальная плоская аппроксимация для отображения, не точная метрическая проекция для расчётов. Если нужен масштаб городской сцены в пределах примерно ±32 Unity units, делите `xMeters` и `zMeters` на **1000**: диапазон данных после такого деления приблизительно `x = −14.8…24.8`, `z = −25.5…22.7`. Высотной модели нет; `height`/`levels` у зданий — необязательные исходные теги, а не вычисленная высота.

## Проверка и ограничения

Перед переносом в репозиторий выгрузка прошла проверку чтения GeoJSON, обратной распаковки gzip, размеров по `manifest.json`, диапазонов координат, замкнутости полигонов и наличия пяти районов, дорог и выборок зданий в каждом из них. На сетке 120×120 точек все пять районов представлены и **0 точек** попали в два района; это выборочная проверка, а не геодезическое доказательство топологии. Подробные числа сохранены в `qa.json`. Скрипты первичной выгрузки и проверки не входят во фронтенд-пакет.

Контуры упрощены в локальных метрах алгоритмом Ramer–Douglas–Peucker: районы 25 м, дороги и реки 12 м, парки 5 м, здания 1.5 м; координаты округлены до 5 знаков после запятой. Дороги и реки относятся к району по середине OSM way и не обрезаны строго по его границе. В `rivers.geojson` есть и другие речные линии; Есиль отмечен `isEsil`. Парки представлены замкнутыми OSM ways; четыре multipolygon relation парков в этом облегчённом наборе не собраны. Здания — **демонстрационная выборка**, а не полное покрытие: радиус 450 м вокруг одной городской точки в каждом районе, до 160 контуров на район. Выбранные числа: Есиль 44, Алматы 160, Сарыарка 160, Байконур 85, Нура 57.

По [сообщению акимата Астаны](https://www.gov.kz/memleket/entities/astana/press/news/details/791094?lang=ru), у города есть шестой район — Сарайшык. По запросу здесь включены только пять перечисленных районов; их совокупность **не является полной границей Астаны**. При сопоставлении источников обнаружено, что Nominatim возвращал устаревший контур Есиля с наложением на Нуру; для итоговых границ использованы непосредственно актуальные геометрии OSM relations через Overpass. Снимок Overpass для границ и транспортных слоёв датирован `2026-09-22T08:45:51Z`; точные времена остальных запросов и OSM way указаны в `manifest.json`.

Во время повторной полной выгрузки Overpass вернул `HTTP 504 Gateway Timeout`. Итоговые файлы собраны из успешной выгрузки; выборки зданий Алматы и Нуры завершены малым запросом к OSM API. Это зафиксированный демонстрационный снимок, а не автоматически обновляемая карта.
